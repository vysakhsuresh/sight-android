================================================================================
You are building Ikshana, an open-source Android app that points a camera at the world
and answers, on the phone, for people who cannot see well first and everyone second. The
repository is github.com/vysakhsuresh/ikshana-android and this folder,
C:\Users\vysak\StudioProjects\ikshana-android, is its clone. Read every word of this
before touching a file.

== WHO YOU ARE WORKING FOR ==
The owner builds a family of Android apps that do the whole job on the phone and upload
nothing: Squish (video, ../squish-android), Still (pictures,
../layerbit-image-editor-android), Sheaf (PDF, ../sheaf-android), Stave (audio,
../stave-android), Deja (screenshots, ../deja-android), LayerLink and Kshana. Ikshana is
the camera that answers. Every tool is free, forever, with no account, no counter, no ad
and no subscription. The reason to believe that is the repository: the app does not
declare the INTERNET permission.

== THE THREE RULES THE OWNER SET, ABOVE EVERYTHING ELSE ==
1. DEPENDABLE ENOUGH TO BE HONOURED. This app is being built to be the most dependable
   thing a blind person in India owns, good enough that the country notices. That is not
   a slogan to put on a screen; it is the standard for every decision. When a shortcut
   and the right way differ, take the right way and write down why. When a feature cannot
   be made dependable, it is not shipped, and the roadmap says so.
2. IT NEVER GOES SILENT. There is nothing Ikshana stops responding to. Every mode has a
   fallback below it, and the last fallback is always a spoken sentence saying what was
   tried and what to do next. A model fails to load: the mode below it works. Nothing is
   found: the app says so and says what to change ("move closer", "more light"). The
   camera is denied: it speaks how to allow it and offers the gallery. The phone is too
   small for a model: the lighter twin takes over and says so. A crash is caught, spoken
   ("Ikshana restarted, say it again"), and the mode returns where it was. A blind person
   holding a phone that has gone quiet is the one outcome this app exists to make
   impossible. docs/FALLBACKS.md lists every failure and the sentence spoken for it, and
   a suite (FallbackChecks) proves every path in the engine's state machine ends in speech.
3. SIZE IS NOT A CONSTRAINT; CAPABILITY OFFLINE IS. Carry the best models that run on the
   phone, not the smallest that fit a download. The Play build takes what asset packs
   allow; the GitHub "full" APK carries everything; the listing states the size and why.
   Scripts, languages and modes are added until the scope is universal: all 22 scheduled
   Indian languages' scripts for Read, then the world's major scripts; Malayalam, Hindi,
   Tamil, then every Indian language with an open voice; and every mode a blind person
   asks for in testing. Phones that cannot carry the large models get the lighter twins,
   chosen at first run by measurement, never by refusing.

== THE MISSION ==
Beat Google Lookout and Gemini's Guided Vision, Microsoft Seeing AI, Be My Eyes and
Envision on the phone, offline, in Indian languages before English, built for the blind
with the display off. The brief is docs/IKSHANA_BRIEF.md in this repository; read it whole
before planning. Its section 5 is the work order and docs/ROADMAP.md is its checklist.
The icon is done: store-assets/icon/build_icon.py builds every launcher and store asset
from one drawing, and app/src/main/res already holds them; keep them, and when the :app
module is created, point the manifest at @mipmap/ic_launcher and @mipmap/ic_launcher_round.

== NON-NEGOTIABLES ==
- Package com.layerbit.ikshana. Versions as Stave's build files unless a library forces
  otherwise; write down why if it does.
- AndroidManifest.xml removes INTERNET and ACCESS_NETWORK_STATE with tools:node="remove"
  and declares CAMERA and nothing else (VIBRATE is normal-level and allowed).
  tools/verify_manifest.py, copied from Stave with CAMERA required and microphone,
  location, contacts and storage forbidden, fails CI if the merged manifest changes on
  these points. Never resolve a merge by deleting those lines.
- Licence GPL-3.0. Every third-party piece and every dataset in THIRD_PARTY_NOTICES.md
  the day it is added, with its licence, and every dataset's licence pinned to the page it
  was downloaded from BEFORE a single line of it is used to train anything. Where sources
  disagree on a licence, write both down and ask the owner before training.
- Modules: :engine (pure Kotlin, imports nothing from android.*, every rule and every
  piece of arithmetic that can be separated from the framework lives here and is executed
  on the JVM), :app (Compose, CameraX, the doors, LiteRT), native under app/src/main/cpp
  only for what Kotlin cannot do fast enough, with a Kotlin twin executed by a suite
  wherever the arithmetic can be mirrored (Stave's LiveTune lesson).
- Models arrive by Play asset pack and inside the GitHub "full" APK, never by a download
  the app performs. Every model has a tier in docs/MODELS.md: fully ours, trained by us on
  open data, or fine-tuned from open weights; a score from the harness; and a lighter
  twin or a named fallback mode for a phone that cannot run it.
- A model is never trusted on the phone until its conversion has been checked against
  the reference run on an input the conversion never saw (Stave's rule: no converter
  worked as delivered; one flat input, one flat output, every state explicit). LiteRT
  1.4.0, never TensorFlow Lite 2.16.1.
- The test set and the harness (P1) exist before any model is trained. Nothing is judged
  by eye or by ear; every claim about a model is a number in docs/MODELS.md.
- Design: voice first; the gestures of the brief's section 4 on every screen; earcons with
  haptic twins; 64 dp targets; the near-black field of the icon with its blue as the one
  accent; Space Grotesk and Fira Code; a name and a state on every control. The
  display-off gate: every screen driven with TalkBack and the display dark, by a blind
  tester before a release. Zero NAF nodes in uiautomator dump is the floor.
- Conventions carried from Squish and Stave (write them into CLAUDE.md): comments say why
  not what; String.format(Locale.ROOT) for anything machine-readable and never cut a
  localised string with an ASCII literal; count code points not chars; three letters is a
  Latin rule; selectable not clickable where a tint is the only mark; Compose compares
  unstable parameters by identity so declare stable collections and never mutate a list
  you have passed down; every float into a file goes through putFinite; a native handle
  can be negative; engine tables reach the screen by id through text/Labels with a
  translation per language the app speaks.
- Verification, in Stave's words: never write "verified" for something this session could
  not observe. ./gradlew :engine:test assembleDebug lintDebug settles a build, and only
  the phone, with a blind tester, settles a feature. Every pure rule gets a tools/jvm
  suite executed with real numbers, and every suite is negative-tested on a copy in the
  scratchpad: put the fault back, run the suite, watch it fail, restore. When a mistake
  escapes, write the check that would have caught it before writing the fix.
- Git: commit after every task with a message that says why; push to main when the build
  passes, without asking. No model name in commits, code or docs. Never force-push.

== THE ORDER OF WORK ==
docs/ROADMAP.md is the checklist, written from section 5 of docs/IKSHANA_BRIEF.md with
every task as a checkbox and its check beside it, with Stave's three marks ([x] seen on a
phone, [~] built not seen, [ ] not built). Add to P0 the two documents the owner's rules
need: docs/FALLBACKS.md (every failure, the mode it falls to, the sentence spoken) and
the FallbackChecks suite over the engine's mode state machine. Work from the first
unchecked item. Do not skip ahead: P0 foundations, P1 the test set and harness, P2 Read
(v0.1), P3 Money and Describe (v0.2), P4 Find (v0.3), P5 Translate (v0.4), P6 Ask (v0.5),
P7 polish (v1.0), then the scripts and languages beyond the first five, one per release,
each with its number in docs/MODELS.md. Each phase ends with its release gate run with a
blind tester if one is available and written into docs/DEVICE_FINDINGS.md with the date;
otherwise the gate goes into docs/PENDING_TESTS.md in order and the item is marked
built-not-seen, never done.

Within a task: write the pure rule in :engine first, write its suite, run it, break it and
watch it fail, restore; then the model or UI piece; then the gate; then commit and push.
Keep CLAUDE.md current: what took an hour to find out goes in there in one paragraph for
the next stranger.
